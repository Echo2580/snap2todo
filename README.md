# Snap2Todo · 截图转待办

> 把通知截图里的事情整理成待办，少抄一遍，执行时也少翻一遍。

我们想做一个个人待办收集工具：把微信、QQ、学习平台、邮件里收到的通知截图丢进来，或者直接粘贴文字，让它帮你整理出要做的事、时间和要求。你检查一下，改改不对的地方，就能存进待办。

**目前处于需求和原型阶段，已有页面原型，完整的识别、保存和提醒流程还在计划中。**

## 现在的痛点

学习和工作中，经常会收到这样的消息：作业周五交，活动周六集合，某份材料明天截止。它们分散在不同软件里，每条都不长，放到一起却很容易漏。

看到通知时，你截了图，想着等会儿处理。截图是存下来了，但要做什么、什么时候做，还是得自己再记一遍。

真到执行的时候，又会遇到另一种麻烦：报告收什么格式？材料交到哪里？集合要带什么？待办里只留了一个标题，于是又得回头翻通知。

我们想先把这段重复操作省下来，让截图里的事情有地方记，执行要求有地方查。

## 第一个功能：截图变待办

第一步先做好一件事：把一张通知截图，整理成可以检查、修改和保存的任务。

- 一张截图里有几件事，就分别整理出来。
- 时间分清开始、截止和提醒；地点、材料、格式、提交渠道一起保留。
- 看不准的地方标出来，让你补充；任务旁边能找到对应原文。

希望用起来是这样的：

```text
上传截图 / 粘贴文字 → 提取任务 → 检查、修改 → 保存待办 → 到点提醒
```

比如收到这条通知：

> 周五22:00前在学习平台提交实验报告，只收PDF。周六上午9:00在图书馆门口集合，记得带学生证。

希望得到的是两件事：

| 待办 | 时间 | 执行要求 |
| --- | --- | --- |
| 提交实验报告 | 周五22:00截止 | 学习平台提交，PDF格式 |
| 参加集合 | 周六9:00开始 | 图书馆门口，带学生证 |

这里的“周五”“周六”还需要结合消息发送日期确定。截图没有给清楚，就提示补充，保留原来的说法。提醒时间则由你另外设置。

## 最小 MVP：先把基本流程跑通

首版先做**单人、本地电脑使用**，计划完成这些功能：

- [ ] 上传一张截图，或粘贴一段文字。
- [ ] 从一份内容里提取一个或多个任务；没有任务时明确提示。
- [ ] 整理标题、时间和执行要求，标出需要补充的信息。
- [ ] 在同一个界面检查、修改任务，一键保存。
- [ ] 查看、修改、完成和删除待办。
- [ ] 从任务回看原截图或原始文字。
- [ ] 轻量保存任务和来源，重新打开后还能接着用。
- [ ] 工具打开期间，到设定时间给出提醒。

**首版不接数据库**，保存方式还在讨论，本地文件是候选方案。账号登录、多人协作和公网部署先放一放，先让自己在电脑上用起来。

提醒也先限定范围：**工具打开、电脑正常运行时提供提醒**。关闭后的提醒，放到后续补充。任务改了时间、已经完成或被删除，对应提醒也要跟着调整。

我们会用实际通知检查它到底省了多少操作：有没有漏任务、有没有记错日期、要改多少地方，以及从导入到保存一共花了多久。

## 后续功能

基本流程用起来之后，再看哪些地方值得继续做：

- [ ] **更方便地导入**：拖入截图、从剪贴板粘贴图片，减少找文件的步骤。
- [ ] **关闭后的提醒**：补充适合电脑端的后台提醒方案。
- [ ] **安卓端**：在手机上收集通知、查看任务和接收提醒。
- [ ] **数据库与数据管理**：按实际需要增加数据库、数据迁移和备份能力。
- [ ] **多截图与去重**：同一件事分在几张图里，能合并；重复导入的内容尽量不重复建任务。
- [ ] **通知变更处理**：新通知改了时间、地点或取消事项时，展示变化，确认后更新任务与提醒。
- [ ] **其他入口**：按需要考虑日历接入、PDF等文件类型。

这些是后续方向，具体顺序会根据真实使用中遇到的问题来调整。

## 技术方向

我们三个人比较熟悉 Python，之前做过 Agent 项目和图书管理系统，也用过 DeepSeek API。

这个项目准备继续以 Python 做后端，前端优先沿用熟悉的方案，任务提取优先验证 DeepSeek API。具体框架、模型和保存方式还没有锁定，会先用一些真实通知试一试。

本地运行指界面、后端和数据保存在自己的电脑上。使用云端模型识别时仍需要联网，截图或文字会发给模型服务处理。
